# Role and Directory Access

**Status:** Current AIDD assignment guide

This guide maps the repository to agent work. It applies to Antigravity roles in `.agents/agents/`, Codex roles in `.codex/agents/`, and a human acting in the same role. It does not create filesystem permissions. The coordinator assigns exact writable files or directories for each bounded work unit; listed areas are candidate locations, not blanket authorization. Read only task-relevant source, never search or publish secrets, and follow the nearest scoped `AGENTS.md`.

## Role assignments

"Write" means edit only the paths named in the work unit and inspect the final diff. Crossing into another role's usual area requires an explicit shared assignment and the relevant scoped instructions. GitHub issue, Project, branch, commit, push, merge, and deployment authorization remain governed by the root rules and life cycle.

## Verification routing

Use `docs/aidd/change-hygiene.md` for checks by changed area. Read `project.json` before choosing an Nx target; do not infer a test target from another project. Database operations follow `docs/aidd/database-access-policy.md`; automated tests may access only the validated test database. OpenAPI edits require the relevant lint and route/parity checks. Process and platform edits require AIDD instruction, link, asset, format, and targeted script checks as applicable. Record skipped checks and their concrete reason in the handoff.
