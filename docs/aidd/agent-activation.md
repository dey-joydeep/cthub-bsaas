# Agent Activation and Shared Roles

**Status:** Current AIDD operating guide

The [development life cycle](development-lifecycle.md) and root and scoped `AGENTS.md` files define shared outcomes, boundaries, and handoffs. Provider files adapt those roles to each runtime. An agent file makes a role available; it does not start a task or approve its own output.

Before activation, the coordinator uses the [role and directory guide](role-directory-access.md) to name the work unit's read targets, writable paths, required checks, and independent reviewer. The agent confirms that assignment before editing. Provider tool availability and GitHub App permissions do not expand the assigned paths.

| Runtime     | Role definitions                                                | Activation                                                                                                                                                                                                                                                                                                                                                          |
| ----------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Antigravity | `.agents/agents/<role>.md` with YAML frontmatter                | In the desktop app, open this repository as the workspace and select a role in the agent picker, or delegate with `invoke_subagent`. In the CLI, use `/agents`, `agy --agent <role>`, or the bounded headless runner `scripts/aidd/run-agy-agent.mjs`. Every delivery role has both `mainAgent: true` and `subagent: true`; the runner pins and verifies the model. |
| Codex       | `.codex/agents/<role>.toml`, registered in `.codex/config.toml` | In the desktop app or CLI, open this repository as the trusted project and ask the coordinator to delegate to a named specialist. Registration and description make the role selectable; a task prompt and available runtime capability are still required.                                                                                                         |

Antigravity does not execute Codex TOML profiles, and Codex does not execute Antigravity Markdown profiles. Keep shared domain rules in `AGENTS.md`, the life cycle, specs, and AIDD policies. Keep provider role files focused on their tools, permissions, model routing, and narrow assignment. The two directories are adapters to different agent runtimes, not separate product teams.

Both Antigravity desktop and CLI discover shared skills and workspace MCP servers under `.agents/`; the portable draw.io server is in `.agents/mcp_config.json`. Codex desktop and CLI use the project `.codex/config.toml` for its registered agents and draw.io server. Authenticated database, design, and GitHub connections remain user-local and must be verified against the target before use. The desktop interfaces must be checked in their own agent and MCP panels after opening this repository; a CLI list proves CLI discovery only.

Codex ignores `profiles` in project-local configuration. Set approval and sandbox behavior through the active desktop/CLI session or user-level configuration, while following the root `AGENTS.md` defaults. The project file registers agents and portable tools; it does not override host-managed permission policy.

For a new machine, first check repository recognition (`agy agents` and `codex mcp list` on the CLI, or the corresponding desktop agent and MCP views), then run `npm run aidd:check`, `npm run aidd:assets`, and `npm run aidd:instruction-drift`. A static check does not prove a model request, MCP connection, or GitHub App action succeeded. If quota or authentication prevents a live probe, record that limitation instead of claiming runtime validation. Apply the [dispatch and resume policy](agent-dispatch-and-resume.md) before starting parallel agents.

Use Antigravity roles for PO, BA, BI, solution and database design preparation, development, QA, DevOps, and release preparation. Use Codex specialists for independent code, contract, architecture, database, product, and security review. A critical security decision needs two separate Codex assessments. Assign each agent a bounded work unit with acceptance criteria and evidence; the AIDD ledger records handoff and resumption. A reviewer does not activate merely because a profile exists: the coordinator must request the review and inspect its result.

The repository currently has role overlap where that helps execution. For example, Antigravity's database architect plans data design, while Codex's database reviewer challenges it. This is intentional separation of author and reviewer. Do not collapse them into one agent profile or let the author supply the independent verdict.
