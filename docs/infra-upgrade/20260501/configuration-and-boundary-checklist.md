# Configuration And Boundary Checklist

This checklist lists the files and decisions that must be reviewed during the upgrade. It is deliberately concrete so implementation does not miss configuration drift.

## Root Workspace Files

| File                   | Required review                                                                   |
| ---------------------- | --------------------------------------------------------------------------------- |
| `package.json`         | Versions, engines, packageManager, scripts, workspaces, remove invalid/stale deps |
| `package-lock.json`    | Regenerate through `npm install`, verify no stale missing manifest deps           |
| `.nvmrc`               | Set to chosen Node LTS baseline                                                   |
| `nx.json`              | Nx plugins, targetDefaults, namedInputs, generators, inference strategy           |
| `tsconfig.base.json`   | Angular 21/TS 5.9 compatibility, path aliases, moduleResolution strategy          |
| `tsconfig.json`        | Project references after migrations                                               |
| `tsconfig.spec.json`   | Split Jest/Vitest types; avoid global Jest for web Vitest projects                |
| `tsconfig.eslint.json` | Keep or remove after flat config validation                                       |
| `eslint.config.js`     | Root flat config, parser service, global ignores                                  |
| `eslint.base.js`       | Boundary rules, strict TS rules, test relaxations                                 |
| `eslint.base.web.js`   | Angular ESLint config and template rules                                          |
| `.eslintrc.json`       | Remove after flat config fully replaces it                                        |
| `jest.config.ts`       | Keep only for backend/global Jest discovery if still needed                       |
| `jest.preset.cjs`      | Keep for backend; remove web dependency on it                                     |
| `.gitignore`           | Add Vitest temporary config patterns if generated by Nx                           |
| `.prettierrc`          | Verify current formatting policy remains accepted                                 |
| `.prettierignore`      | Ensure coverage/cache/dist/vitest temp files ignored                              |
| `.redocly.yaml`        | Verify Redocly 2.30 compatibility                                                 |

## Nx Plugin Strategy

Current `nx.json` plugins:

```json
["@nx/eslint/plugin", "@nx/jest/plugin"]
```

Target strategy:

- Keep `@nx/eslint/plugin`.
- Keep `@nx/jest/plugin` scoped to backend/API/e2e Jest configs only.
- Add `@nx/vitest/plugin` scoped to web/shared Vitest configs only.
- Avoid broad plugin overlap where Jest and Vitest infer the same target name.
- If inferred tasks are enabled, document precedence and override points.

Nx docs note that plugin order matters when plugins infer the same target name. This is important when Jest and Vitest coexist.

Specific checks:

## Tag Model

Target tag dimensions:

```text
type:app | type:lib | type:e2e
platform:web | platform:server | platform:shared
scope:web-admin | scope:web-customer | scope:web-partner | scope:web-core | scope:web-ui | scope:web-config
scope:server-core | scope:server-contracts | scope:server-data | scope:server-infrastructure | scope:server-feature
scope:shared
layer:app | layer:feature | layer:ui | layer:core | layer:contracts | layer:data | layer:infra
```

Minimum normalization:

- Every project gets exactly one `type:*` tag.
- Every project gets exactly one `platform:*` tag.
- Every library gets a meaningful `scope:*` tag.
- Server libs get a `layer:*` tag.
- Web libs get a scope/layer tag that reflects whether they are app-specific, core, config, or UI.

## Boundary Rules

Target boundary intent:

| Source                        | Allowed dependencies                                                       |
| ----------------------------- | -------------------------------------------------------------------------- |
| Web apps                      | Web libs and shared only                                                   |
| Web app-specific feature libs | Same web app scope, web core/config/ui, shared                             |
| Web core libs                 | Web core/config/shared only                                                |
| Web UI                        | Shared only; no app-specific deps                                          |
| Shared                        | Shared only; no Angular, Nest, Node-only APIs unless guarded and justified |
| Server app                    | Server libs and shared only                                                |
| Server feature                | Server contracts/core/data/infra/shared as needed                          |
| Server infra                  | Contracts/core/data/shared; no feature deps                                |
| Server data                   | Contracts/core/shared; no feature deps                                     |
| Server core                   | Contracts/shared; no feature deps                                          |
| Server contracts              | Shared only                                                                |

Required ESLint checks:

- `@nx/enforce-module-boundaries` remains `error`.
- Add `notDependOnLibsWithTags` where clearer than permissive allow lists.
- Ban web imports from `@cthub-bsaas/server-*`.
- Ban server imports from `libs/web/**`.
- Ban deep imports across package boundaries.
- Evaluate targeted `no-restricted-imports` rules for server-core deep imports after package-root exports are confirmed.
- Consider `banTransitiveDependencies: true` after package/workspace metadata is cleaned.

## Angular ESLint

Required checks:

- `angular-eslint` upgraded to Angular 21-compatible version.
- Angular template lint runs for all app/lib templates.
- Component selectors are consistent:
  - app-specific apps may use app prefix.
  - shared libs should use `cthub` or `lib` only if that is the chosen convention.
- Directive selectors use camelCase attributes.
- Project-specific `quality.config.js` files are either wired into lint or removed if stale.

## Angular Official Update Guide Checkpoint

Phase 3 must include the official Angular Update Guide as a checklist, not only Nx migrations.

Use:

```text
https://angular.dev/update-guide?v=20.0-21.0&l=3
```

Required selections:

- Angular 20.0 to Angular 21.0.
- Advanced complexity.
- Angular Material.
- Windows.

Required review items:

- Angular/Node/TypeScript/Zone.js compatibility.
- Angular Material and CDK migration notes.
- SSR and hydration behavior.
- Windows-specific command/path caveats.
- Any warnings emitted by Angular migrations.

Do not treat optional Angular modernization as part of the upgrade unless separately scoped. Zoneless adoption, broad Signals refactors, and large UI rewrites should remain follow-up work.

## Testing Config Split

Target split:

| Area                | Runner              | Config                                                                 |
| ------------------- | ------------------- | ---------------------------------------------------------------------- |
| Angular apps/libs   | Vitest              | `vitest.config.ts` or equivalent Nx-generated config                   |
| Shared pure TS      | Vitest candidate    | only after pilot                                                       |
| Backend server libs | Jest                | existing `jest.config.ts`, `jest.unit.config.ts`, `jest.int.config.ts` |
| API app tests       | Jest                | existing app config until separately migrated                          |
| API e2e             | Jest                | keep                                                                   |
| Web e2e             | existing e2e runner | not changed by this plan unless required by Nx migration               |

Do not keep Jest globals in web `tsconfig.spec.json` after web projects move to Vitest.
